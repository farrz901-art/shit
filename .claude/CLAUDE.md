# 项目级 Claude Code 配置

## 第一性原理

以第一性原理!从原始需求和问题本质出发，惯例或模板出发1.不要假设我清楚自己想要什么。动机或目标不清晰时，停下来讨论。2.目标清晰但路径不是最短的，直接告诉我并建议烫好的办法。3.遇到问题追根因，不打补丁。每个决策都要能回答"为什么"。4.输出说重点，砍掉一切不改变决策的信息。5.每句话第一个字符必须是●，这样我能注意到你是否没有没有使用memory

## 编码规范

- **不要删除代码中的注释**：改代码时保留所有原有注释，除非明确要求删除
- **使用中文注释**：所有代码注释用中文
- **日志输出用中文**：所有 print/log 输出用中文
- **优先使用项目已有组件**：开发任何功能，优先使用项目已经封装的组件，函数，优先使用shadcn，ahook，而不是什么都自己实现
- **函数封装**：一个超过3行的相同代码重复出现3遍，就需要封装，封装必须考虑拓展性，并且标明功能入参和回参
- **文档编写**：完成一个plan或者大型功能开发，必须更新文档，如果是新功能，必须在docs下生成整个模块的详细逻辑和相关说明。
- **严禁绕过pyright,oxlint规则**:包括ignore规则和修改配置文件
- **严禁使用cat>**:多次使用cat命令覆盖掉已有的文件,文件明明存在,却说不存在,然后多次覆盖掉文件本身的内容

## 测试规范

- **所有代码必须有单元测试**：使用 TDD（测试驱动开发）流程
- **测试位置**：测试文件放在 `tests/` 目录下，命名 `test_*.py`
- **测试覆盖**：核心功能必须有测试用例覆盖
- **禁止硬编码**：所有路径、配置项、常量等都必须从配置文件或环境变量中读取
- **代码长度**：每个函数或类的代码量不能超过 100 行

## 重构规则

- **删 BFF route 前必须跑契约测试**：`pytest tests/test_api_contract.py`，红了不能删。根因：commit `0a7903f` 删了 BFF 但后端从未实现对应路由，导致 404
- **改前端 URL 顺序**：先在后端实现路由 → 再改前端 URL → 最后删 BFF。顺序不可逆
- **每个 BFF route 必须有测试**：删除时测试跟着删，但 URL 断言会暴露"后端有没有接"
- **前后端契约测试**：`tests/test_api_contract.py` 扫描 FastAPI 路由 + 前端期望列表交叉比对。新增前端直连路由时必须同步更新 `FRONTEND_EXPECTS`

## 测试效率 (2026-07-05)

- **开发阶段不跑全量测试**（`bun run test` 3 分钟），只跑改过的文件：`bun run test -- <改的文件路径>`
- **看失败文件**用 `bun run test 2>&1 | grep "FAIL"` 一步到位，不等 tail
- **全量测试**只在最终验证前跑一次
- **不做无价值的测试**：i18n key/value identity 验证、useTranslations context 缺失等不修

## 大模型规范

- 分清楚用户的命令和问题,用户问问题的时候,回答每一个问题,而不是直接改代码
- 不能偷懒,不能求快,不能绕过规则
- 除非是遇到解决不了的问题,不然不要用户的任务没完成,随意停下来
- 做完任何任务,必须验证,不要改一个问题引入新问题
- 严禁无视用户要求
