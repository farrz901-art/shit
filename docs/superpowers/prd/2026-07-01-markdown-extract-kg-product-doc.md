# 知识图谱智能抽取服务 产品方案（12 页 PPT 版）

**版本**：v1.0
**日期**：2026-07-01

---

## 第 1 页：一句话总结

### 我们的方案

**上传一个 Markdown 文件，自动抽出里面的"实体—关系—实体"，人工校对一下，3 个出口任选（写 Neo4j / 导 JSONL / 导 Cypher 脚本）。**

解决两件事：
- 知识图谱录入从"人工 1 周"变"自动 3 分钟"
- 抽取的规则升级为图谱一等公民（独立 Rule 节点），跨文档可复用

---

## 第 2 页：为什么做（现状痛点）

**手工录入慢**：1 万条三元组 = 1 人 1 周。中文文档里到处都是"X 是 Y 的 Z"、"X 符合标准 Y"这种结构化信息，本应让机器抽。

**容易录错**：同一型号在不同地方写不同名，图谱查询不到。

**隐性规则无法复用**：现在 LLM 抽出的"兼容 / 依赖 / 互斥 / 降容"只是关系上的标签，没法跨文档合并、版本管理、选型时直接调用。

**没有中间产物**：想喂给 ChatGPT/Claude 做二次分析，只能截图，没有标准格式导出。

---

## 第 3 页：用户旅程（一图看懂）

```
上传 .md  →  后台智能抽取  →  表格预览校对  →  三个出口任选
```

**第一步：上传**
- 进入 `/knowledge/extract` 页面
- 选抽取器（4 选 1）+ 切片策略（3 选 1）+ 上传 .md 文件

**第二步：后台异步抽取**
- 不阻塞用户，进度条实时刷新
- LLM 抽取：~30 秒/万字；spaCy 抽取：~2 秒/万字

**第三步：预览校对**
- 实体表 + 关系表
- 可勾选（取消不想要的）/ 可编辑（改正错的）

**第四步：3 个出口**
- **写 Neo4j** / **导出 JSONL**（给 LLM）/ **导出 Cypher 脚本**（DBA 手动）

## 第 4 页：2 种抽取器（用户可选）

| 抽取器 | 适用场景 | 准确率 | 速度 | 成本 |
|---|---|---|---|---|
| **LLM + Pydantic** ⭐主力 | 通用中文文档、半结构化叙述 | 88-97% | 慢（5-30秒/文档） | 中（API 收费） |
| **spaCy 规则** | 英文技术文档、术语库 | 70-85% | 快 | 0（本地） |

**默认选项**：**LLM + Pydantic**（大多数中文文档用它）

**为什么砍掉 HanLP / REBEL**：业界 2026 H1 共识 LLM + JSON Schema 强约束是 SOTA（88-97%），纯 NLP（HanLP/REBEL/spaCy）已退守高吞吐限定领域，不再作为通用方案。

---

## 第 5 页：3 种切片策略（用户可选）

**为什么需要切片？** LLM 有上下文窗口限制（8K-200K tokens），超长输入会降低准确率。

| 切片器 | 原理 | 适用文档 |
|---|---|---|
| **按 heading 切** ⭐默认 | 按 Markdown `# / ## / ###` 天然分段 | 技术文档、规范、手册 |
| **按 token 滑窗** | 固定窗口 + 10-20% 重叠 | 任何纯文本（兜底） |
| **按语义切** | 句切 + Embedding cosine 距离，相邻相似就合并 | 论文、报告、叙述性长文 |

## 第 6 页：3 个出口

| 出口 | 格式 | 何时用 |
|---|---|---|
| **A. 写 Neo4j** ⭐主力 | 直接写入图数据库 | 日常入库，准备做 RAG 检索 |
| **B. 导出 JSONL** | 每行一个 JSON 对象 | 喂给 ChatGPT/Claude 做二次分析 |
| **C. 导出 Cypher 脚本** | 标准 Neo4j 脚本 | DBA 审查后手动执行（合规要求） |

**JSONL 示例**：
```jsonl
{"head":"比亚迪海豹","relation":"符合","tail":"GB/T 18384","rule_type":"factual","confidence":0.95}
{"head":"800V平台","relation":"兼容","tail":"400V充电桩","rule_type":"compatibility","confidence":0.88}
```

**Cypher 示例**：
```cypher
MERGE (a:Product {model: '比亚迪海豹'})
MERGE (b:Standard {code: 'GB/T 18384'})
MERGE (a)-[r:COMPLIES_WITH]->(b) ON CREATE SET r.rule_type = 'factual';
```

## 第 6.5 页：隐性规则升级为一等公民

### 痛点

LLM 抽出来的规则只是关系上的 `rule_type` 标签，**无法跨文档复用、合并、版本管理**，选型时无法直接调用。

### 核心思路

把规则升级为图谱**一等公民**，引入独立 `Rule` 节点，跟产品、规格平级。

### 五类规则四路落地

| 规则类型 | 落地方式 |
|---|---|
| **Factual**（事实） | 写成产品属性，**不单独建节点** |
| **Compatibility**（兼容） | 关系 + `Rule` 节点，记推荐组合 + 适用条件 |
| **Dependency**（依赖） | 关系 + `Rule` 节点，记强制配套 + 版本要求 |
| **Exclusion**（冲突） | 关系 + `Rule` 节点，标记禁止组合 + 严重程度 |
| **Derating**（降容） | **必然**进 `Rule` 节点，存计算公式 + 变量单位 |

### 治理机制

- 按规则类型四路分发
- 条件哈希去重
- 跨文档合并同源规则

### 业务价值

规则从一次性标签 → **可治理的知识资产**，选型时直接查询 `Rule` 拿到适用条件与计算公式，跨文档一致、版本可追溯、业务可演进。

## 第 7 页：用户界面（4 个页面）

**页面 1：抽取任务创建**（`/knowledge/extract`）
- 下拉选抽取器（2 选 1）+ 切片策略（3 选 1）+ 切片大小
- 拖拽上传 .md 文件（最大 5MB）

**页面 2：异步进度**（`/knowledge/extract/{task_id}`）
- 进度条 + 实时刷新（如 "████████░░ 72% (18/25 chunks)"）
- 显示已用时间 + 预计剩余

**页面 3：预览校对**（`/knowledge/extract/{task_id}/preview`）
- 两个 Tab：实体表 / 关系表
- 可勾选（取消不想要的）+ 可点击单元格编辑（改正错的）

**页面 4：3 个出口弹窗**
- 写 Neo4j 确认弹框
- 导出 JSONL/Cypher 自动下载

## 第 8 页：典型使用场景

**场景 1：技术文档 → 知识图谱**（主力，80% 用户）
- 拿到《比亚迪海豹技术手册 v2.3》PDF → 前序流水线转 Markdown
- 选 LLM + heading 切 + 2000 字 → 上传 → 3 分钟抽完
- 预览勾掉 5 条、改 2 条 → 写 Neo4j → 多 47 个实体、89 条关系

**场景 2：导出给 LLM 做问答对**（AI 训练师）
- 抽完一批关系 → 导出 JSONL → 喂给 Claude："基于以下三元组生成 50 个问答对"

**场景 3：DBA 审查后入库**（合规要求）
- 抽完一批关系 → 导出 Cypher → DBA 人工审查脚本 → 手动在生产 Neo4j 执行

**场景 4：术语库抽取**（英文文档）
- 上传英文技术规范 .md → 选 spaCy 规则 + token 滑窗 → 2 秒抽完 → 写 Neo4j

## 第 9 页：访问模式

### 统一的知识图谱

项目是一个**统一的知识图谱**，不分租户。

### 三类角色

| 角色 | 权限 |
|---|---|
| **管理员** | 通过 `/knowledge/extract` 页面上传 Markdown、抽取、校对、写 Neo4j、查询、修改 |
| **DBA** | 接收 Cypher 脚本，审查后手动在生产 Neo4j 执行 |
| **外界用户** | **只能通过大模型**访问知识图谱，不直接访问 Neo4j |

### 关键设计

- Neo4j 不做用户隔离，是统一知识资产
- 写入权限收口在管理员端 + DBA 端
- 外部查询全部走 LLM（RAG 检索 + 生成），LLM 是唯一对外入口

## 第 10 页：风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| LLM 准确率不达预期（< 80%） | 用户不信任 | 校对页必走、人工编辑、2 抽取器可切换 |
| 大文件（5MB）抽取超时 | 用户体验差 | 后台异步 + 进度条 + 可取消 |
| LLM API 涨价 | 成本失控 | 提供本地 Qwen2.5-7B 选项 |
| 中文术语多样性（"快充" vs "闪充"） | 同一概念被拆开 | v1.1 加实体归一化 |
| 规则去重误杀 | 同源规则被错误合并 | 条件哈希 + 人工审核 + Rule 节点版本号 |
| DBA 执行 Cypher 出错 | 图谱数据污染 | DBA 审查 + dry-run + 回滚脚本 |

## 第 11 页：未来路线图

### v1.1（3-6 个月后）
- **实体归一化**：编辑距离 + Embedding 自动合并"快充/闪充"
- **Rule 节点派生**：把 `rule_type` 关系转成显式 Neo4j Rule 节点
- **规则推理**：基于 Rule 节点做"传递闭包"推理（如 A 兼容 B + B 兼容 C → A 兼容 C）
- **批量抽取**：一次上传多个 Markdown 文件

### v1.2（6-12 个月后）
- **流式抽取**：边上传边抽（秒级返回）
- **PDF/DOCX 直抽**：跳过前序转换流水线
- **RAG 集成**：抽取结果自动进 Dify dataset
- **自动评估**：抽取准确率自动打分

### v2.0（12+ 个月后）
- **多模态抽取**：图表/公式/图片 OCR → 实体
- **跨文档指代消解**："前文提到的 X" → 实际实体
- **主动学习**：用户校对反馈回流训练数据，持续提升
