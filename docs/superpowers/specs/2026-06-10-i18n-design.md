# 国际化 (i18n) 设计

> 2026-06-10 · Brainstorming → Spec
> Status: 待用户 review

## 1. 目标

next-intl 集成 + 678 处中文提取为 `t()` 调用 + `messages/zh.json` + `messages/en.json` + SettingsDialog 语言行启用 + vitest 语言切换断言.

不在范围:
- 后端 API 错误翻译 (原样展示)
- RTL 支持
- 后端 Python 代码改英文

## 3. 路由策略

**路径前缀 + cookie 降级**:
- URL: `/zh/knowledge/nodes`, `/en/knowledge/nodes`
- middleware: 检测 URL 前缀 → 有则用; 无则读 cookie `NEXT_LOCALE` → 有则重定向; 无则默认 `zh`
- cookie: `NEXT_LOCALE=zh|en` (next-intl 自动管理)
- SettingsDialog 语言切换: 调 `useRouter().push(\`/\${newLocale}/\${currentPath}\`)` + 设 cookie

## 5. SettingsDialog 语言行启用

```diff
- {/* 行 2: 语言 (占位 disabled) */}
- <SettingRow label="语言" disabled>
-   <Badge variant="outline">中文</Badge>
+ {/* 行 2: 语言 (活) */}
+ <SettingRow label={t("settings.language")}>
+   <Select value={locale} onValueChange={(v) => router.push(`/${v}/${currentPath}`)}>
+     <SelectItem value="zh">中文</SelectItem>
+     <SelectItem value="en">English</SelectItem>
+   </Select>
  </SettingRow>
```

## 6. 日期/数字格式

- `animated.tsx` CountUp: `toLocaleString("en-US")` → `toLocaleString(locale)`
- `EvalListRow.fmtDate()`: 改用 `Intl.DateTimeFormat(locale, {...})`
- `ConversationList.formatRelativeTime()`: 中文硬编码 → `Intl.RelativeTimeFormat(locale)` + 翻译 key

## 7. 测试策略

每个翻译过的 `page.test.tsx` 加 1 个语言切换断言:
```tsx
it("切换英文后显示英文文本", () => {
  render(<Page />, { wrapper: createWrapper("en") });
  expect(screen.getByText("Node List")).toBeInTheDocument();
});
```

`createWrapper(locale)` 是测试工具函数, 包 `NextIntlClientProvider` + 传入对应 messages.

## 9. 风险

- **路由大重构**: 所有页面移入 `[locale]/` 目录, 19 个文件 + 所有内部 `<Link href="...">` 要加 locale 前缀. 影响面大, 需仔细回归
- **API 路由不动**: `web/app/api/` 不移入 `[locale]/`, 保持原路径
- **middleware 逻辑**: 路径前缀 + cookie 降级逻辑需精确, 否则 404 或死循环重定向
- **678 处提取工作量**: 每处中文要: 找到最近的 `'use client'` 组件 → import `useTranslations` → 改 `t('key')` → 写 messages JSON. 纯机械但量大
- **测试 wrapper**: 需要写 `createIntlWrapper(locale)` 工具函数, 给所有 page.test.tsx 用
- **next-intl 版本**: 需要 next-intl 4.x (支持 App Router), 当前 bun.lock 未安装
