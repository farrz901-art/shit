# 段落标注优化 — 产品需求文档 (PRD)

**编号**: PRD-2026-07-07-002 · **日期**: 2026-07-07 · **作者**: 产品 / 业务
**对应 spec**: [2026-07-07-paragraph-annotation-optimization-design.md](../superpowers/specs/2026-07-07-paragraph-annotation-optimization-design.md) · **上期**: [2026-07-02-pdf-pre-analysis-prd.md](./2026-07-02-pdf-pre-analysis-prd.md)

---

## 1. 背景与契机

上期 3 周落地, 收集 4 个痛点: 英文 PDF 命中 0 / 中文语义混 / 段落假阳性 40% / 中文跨页表漏检. 机会: 用 "多语言 + 权重 + 密度" 三维评分, 一份清单覆盖中英德, 业务验收时间大幅缩短.

## 2. 目标用户

**主用户 (工程师)**: 拿预分析产物验收. 想要: 多语言命中、硬约束优先排序、跨页表自动识别.
**间接受益方 (业务方 / 主管)**: 看报告. 期望: 验收回流率下降, 多语言手册也能提前发现漏抽.

## 3. 用户故事

**故事 1 — 英文手册可用**

```
作为工程师, 上传 D81.1 英文 PDF → 拿到 50+ 段加权清单
Top 段全是 "danger / warning" 硬约束, 我直接进设计审查.
```

**故事 2 — 中文不退化**

```
作为工程师, 升级工具后, 旧脚本 (读 CSV 前 4 列) 仍能跑.
5 个旧中文关键词命中段原样出.
```

**故事 3 — 跨页表自动识别**

```
作为工程师, 上传含跨页表的中文 PDF.
footer "续表 / 接下页 / continued" 自动命中, 多列表格不重复触发.
```

**故事 4 — 工程透明**

```
作为运维, 本期不加新 PyPI 依赖, 仅启用项目已装库.
Dockerfile 加一行下载 spacy 英文模型, 1 个 PR 上线.
```

## 4. 功能范围

### 4.1 本期做

| 编号 | 功能 | 验收 |
|---|---|---|
| F1 | **多语言规则库 (4 类)** — 否定 / 义务 / 条件 / 允许 | 英文 PDF 命中 ≥ 50 段 |
| F2 | **安全 / 推荐权重** — 硬约束加权, 软建议降权 | Top 段可视化排序 |
| F3 | **智能段落切分** — 表格与正文分离 | 段落噪音 ↓ 至 5% |
| F4 | **跨页表识别** — 中英 footer 16 词 + 多列去重 | 跨页准确率 75% → 92% |
| F5 | **缩写识别** — "必须不 / 不可" 缩写不漏检 | 英文缩写段 0 漏 |
| F6 | **中文兼容** — 旧 5 关键词命中段原样出 | 业务侧无感知 |

### 4.2 本期不做

NF1 关键词可视化编辑 · NF2 多语自动识别 · NF3 前端密度可视化 · NF4 LLM 二次校验 · NF5 扫描件 OCR · NF6 表格内规则段.

## 5. 用户体验与界面

工程师侧: 打开 CSV, 按密度列降序看 Top 段, 直接进设计审查. 不再二次过滤.
业务侧: 旧入口与详情页不变, 仅 CSV 列数扩, 下游兼容.

## 6. 验收标准

**Happy (主管)**: 英文 PDF 命中 ≥ 50 段 / 中文不退化 / 旧脚本兼容 / 跨页检测准.
**边界 (工程师)**: 缺模型明确报错 / 旧 yaml 仍可跑 / 跨页多列不重复.
**性能**: 50 页 ≤ 90s · 200 页 ≤ 240s.

## 7. 时间盒

4 天: ① 规则库 + 中文不退化 ② 段落切分 + 跨页 ③ spacy + CSV 扩列 ④ 验收.

## 8. 不做的事

不联动 admin UI · 不自动识别语种 · 不暴露 NER · 不调 LLM 校验 · 不改前端 · 不识别扫描件.

## 9. 风险与依赖

- **spacy 模型** (~40MB): Dockerfile 下载一次即可, 镜像增量稳定
- **中文退化**: 旧 in 子串逻辑保留, 双轨并存
- **跨页误合并**: 同 footer 文本去重, 不同 footer 不合并
- **依赖**: spacy / regex / tiktoken / pymupdf, 全部已装

## 10. 监控指标

- 英文 PDF 命中段数 (基线 ≥ 50)
- 中文退化率 (< 5%)
- spacy 503 错误率 (< 2%)
- 工程师清洗工时 (旧 2h → 新 15min)
- 主管验收回流率 (期望 15% → 3%)

## 11. 业务决策 (2026-07-07 已批准)

1. 4 类规则 + 2 类权重 (非 7 类, 跟业界 deontic 标准对齐)
2. 段落切分默认智能模式, 旧模式 opt-in
3. 0 新增 PyPI 依赖
4. 4 天交付 (含验收缓冲)
