先把结论说清楚：
1. 在 Dify 里，“短期记忆”靠的是 **Chatflow + LLM 记忆 + 会话变量**，不需要你自己写历史对话管理。  
2. 从外部调用 Dify 对话接口时，**只需要维护一个 `conversation_id`**，Dify 会自动帮你把历史对话喂给模型，你不用自己拼 `messages` 数组。
下面分三步讲：  
- Dify 内部怎么实现短期记忆  
- 外部调用时怎么配置历史对话  
- 会话变量怎么配合用
---
## 1. Dify 内部：短期记忆是怎么实现的？
### 1.1 必须用 Chatflow 应用
Dify 里只有 **Chatflow（对话流）** 才有多轮记忆能力，Workflow / Completion 类型是单次、无状态的。
创建应用时：
- 新建应用 → 类型选 **“对话型应用 / Chatflow”**
### 1.2 在 LLM 节点里开“记忆（Memory）”
在 Chatflow 编辑页：
1. 双击 LLM 节点；
2. 找到 **“记忆 (Memory)”** 开关，打开；
3. 设置 **“记忆窗口”**，比如 10，代表模型最多能看到最近 10 轮（用户+助手）对话。
这样，同一会话里，Dify 会自动把前 N 轮对话拼到 LLM 的上下文中，你不用自己管理。
### 1.3 在 Prompt 里引用上下文
在 LLM 节点的 System Prompt 中，用类似：
```text
你是一个智能助手。请根据对话历史和当前问题，给出连贯的回答。
对话历史：{{#context#}}
```
`{{#context#}}` 是 Dify 内置变量，代表当前会话的对话历史。  
这样模型就能“看见”之前的对话，实现短期记忆。
---
## 2. 外部调用：历史对话怎么配置？
从外部（你的后端）调用 Dify 时，**不要自己维护历史消息列表**，而是：
- 第一次请求：`conversation_id` 留空；
- 从第一次响应里拿到 `conversation_id`；
- 后续所有请求都带上这个 `conversation_id`。
Dify 会自动把该会话的历史对话喂给 LLM，你只需要传当前这轮的 `query`。
### 2.1 核心 API：`/v1/chat-messages`
官方对话型应用的标准接口是：
- URL：`https://api.dify.ai/v1/chat-messages`（自托管则换成你的域名）
- Method：POST
- 关键字段：
```json
{
  "inputs": {},           // 传入应用定义的变量（可选）
  "query": "用户当前问题",
  "response_mode": "blocking",   // 或 "streaming"
  "conversation_id": "",  // 首次为空，后续填上次返回的值
  "user": "user-123"      // 你自己定义的用户标识
}
```
响应里会返回：
```json
{
  "answer": "...",
  "conversation_id": "sess_xxx",  // 后续就用这个 ID
  "message_id": "...",
  "metadata": { ... }
}
```
### 2.2 Python 示例：多轮对话保持短期记忆
```python
import requests
API_URL = "https://api.dify.ai/v1/chat-messages"  # 或你自托管地址
API_KEY = "app-xxxxxxxx"  # 你的 Dify API Key
headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json",
}
def chat_once(query: str, conversation_id: str | None = None, user: str = "user-123"):
    data = {
        "inputs": {},
        "query": query,
        "response_mode": "blocking",
        "user": user,
    }
    if conversation_id:
        data["conversation_id"] = conversation_id
    resp = requests.post(API_URL, headers=headers, json=data)
    resp.raise_for_status()
    return resp.json()
# 第一次调用
r1 = chat_once("我叫张三，我最近在学 Python")
print(r1["answer"])
conv_id = r1["conversation_id"]  # 保存下来
# 后续调用，同一个 conversation_id
r2 = chat_once("我刚才说我叫什么名字？", conversation_id=conv_id)
print(r2["answer"])
```
**关键点：**
- 你不需要自己把历史对话写成 `messages: [{role, content}, ...]`；
- Dify 内部会根据 `conversation_id` 自动维护历史，并在 LLM 调用时拼好上下文。
### 2.3 流式调用（SSE）
如果你要逐字输出，把 `response_mode` 改为 `"streaming"`，返回的是 SSE 事件流，每行类似：
```text
data: {"event": "message", "answer": "一部分", ...}
data: {"event": "message_end", "metadata": {...}}
```
前端按 SSE 解析即可，`conversation_id` 依然从第一条事件中取。

## 3. 会话变量：短期记忆里的“结构化状态”
如果只是“记住前面说了什么”，LLM 的记忆窗口就够了；  
但如果你还要在本次会话里存一些**结构化状态**（比如订单号、当前步骤、用户偏好），就要用 **会话变量（Conversation Variables）**。
### 3.1 在 Dify 里配置会话变量
1. 进入 Chatflow 编辑页 → 左侧菜单「变量」→ 「会话变量」标签；
2. 新建变量，例如：
   - `order_id`：String
   - `current_step`：String
   - `user_profile`：JSON/Object。
这些变量会随 `conversation_id` 自动创建/销毁，刷新页面、换设备只要还是同一个会话 ID，变量就还在。
### 3.2 在工作流中读写会话变量
- 在 LLM / 代码 / 模板等节点里，可以用：
  - `{{session.order_id}}` 读取
  - 在“变量赋值”节点中更新。
- 也可以通过 API 操作会话变量：
  - 获取：`GET /v1/conversations/{conversation_id}/variables`
  - 设置：`POST /v1/conversations/{conversation_id}/variables`
  - 删除：`DELETE /v1/conversations/{conversation_id}/variables/{name}`。
### 3.3 和外部调用结合
外部调用时，如果你想给会话变量赋初值，有两种方式：
1. 在请求体 `inputs` 里传，例如：
   ```json
   {
     "inputs": {
       "order_id": "12345"
     },
     "query": "这个订单发货了吗？",
     "conversation_id": "...",
     "user": "user-123"
   }
   ```
   Dify 会把 `inputs` 中的值写入会话变量。
2. 通过会话变量 API 单独设置（更灵活，适合后端做状态管理）。
---
## 4. 小结：短期记忆怎么搭，历史对话怎么配
1. **Dify 内部：**
   - 应用类型：Chatflow；
   - LLM 节点：开启 Memory + 设置窗口；
   - System Prompt：用 `{{#context#}}` 引入对话历史。
2. **外部调用：**
   - 用 `/v1/chat-messages` 接口；
   - 第一次 `conversation_id` 为空；
   - 从响应拿到 `conversation_id` 后，后续请求都带上；
   - 你只传当前 `query`，**不用自己拼历史消息**。
3. **会话变量：**
   - 用于存本次会话的结构化状态（订单号、步骤、用户画像等）；
   - 可通过 `inputs` 或会话变量 API 设置。
